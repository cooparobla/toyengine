# Scene component reference

Every component a scene or object asset can use, with its exact keys. Colours are
`{ r, g, b }`, vectors `{ x, y, z }`; a partial map keeps the defaults of the missing fields
(except Transform -- write all three axes). **Unknown types, unknown keys, and (unless noted)
unknown enum values are silently ignored or fall back to the default.** ParticleSystem enums
and WaterBody `mode` throw on unknown values instead.

Parsers: `libs/libcoopa/coopa/scene/scene_loader.h` (Transform, objects),
`libs/gfxcoopa/gfxcoopa/engine/components/register.h` (rendering),
`toyengine/scene/register.h` (engine components), `toyengine/save/register.h` (SaveId), `libs/physxcoopa/physxcoopa/physx_yaml.h`
(physics), `toyengine/particles/particle_yaml.h`, `libs/libcoopa/coopa/animation/animation_yaml.h` (Animator, TwoBoneIK, LookAtIK),
`libs/uicoopa/uicoopa/ui_yaml.h` and `builder/ui_composites_yaml.h`, `libs/sfxcoopa/sfxcoopa/sfx_yaml.h`,
`libs/physxcoopa/physxcoopa/nav_yaml.h` (navigation).
When in doubt, open the parser -- it is short and authoritative.

## Objects

```yaml
- name: thing            # default "Object"
  active: true           # default true
  prefab: objects/x      # optional object asset (= inherit_from:); "path#ObjectName" picks a child
  components: [ ... ]    # `- type: Foo` entries
  children: [ ... ]
```

Prefab instance merge: the instance's root Transform (or RectTransform) **replaces** the
prefab's; other components match by type (add `id:` to tell repeated types apart) and
deep-merge; children match by `name` and merge; unmatched entries are appended; `remove: true`
on a component or child deletes it.

## Core

| Component | Keys (default) |
|---|---|
| Transform | `position`, `rotation` (Euler degrees, X then Y then Z), `scale` |
| Camera | `main` (false; first started wins if none), `projection` (`Perspective` / `Orthographic`), `fov` (60, vertical deg), `orthographic_size` (3, half-height), `near_clip_plane` (0.1), `far_clip_plane` (1000), `lens` (50 mm), `sensor_width` (36), `aperture`, `focus_distance` (0 = config), `focus_object` (`a:b` path) |
| CameraController | `mode` (`orbit` / `fly` / `first_person`), `tracker` (object name to follow; FirstPerson rides it), `target`, `target_offset`, `distance`, `yaw_deg`, `pitch_deg` (unset = from the start Transform), `min_pitch_deg` (0), `max_pitch_deg` (85), `min_distance` (0.5), `max_distance` (100), `follow_smoothing` (10), `movement_smoothing` (0), `mouse_sensitivity` (0.15), `zoom_speed` (1), `invert_x`, `invert_y`, `capture_cursor` (true), `auto_rotate_deg_per_sec` (0), `key_orbit_speed_deg_per_sec` (0; Orbit: WASD / arrows turn the camera at this rate -- leave at 0 wherever WASD drives something else), `key_pan_speed` (0; Orbit with no `tracker`: arrows slide the static `target`, m/s -- pair with `look_button: right` for a right-drag-to-look, arrows-to-move rig), `look_button` (empty = turn continuously; `left` / `right` / `middle`), `move_speed` (5), `look_speed_deg_per_sec` (90), `collide` (true; Orbit with a `tracker` sphere-casts and pulls in when geometry blocks the view), `collision_radius` (0.2), `collision_in_speed` (25), `collision_out_speed` (4; 1/s, 0 snaps), `eye_height` (1.6; first_person, above the tracker's origin), `first_person_pitch_limit` (85) |
| PlanetCameraFit | Authored on the camera object beside its `Camera` and `CameraController`; frames the scene's `planet: true` Terrain and is a strict no-op without one. Derives `max_distance` (= `R / sin(fov/2) * frame_margin * max_distance_scale`), `min_distance` (= radius + MEASURED peak + `min_clearance`), `zoom_speed` (= range / `zoom_notches`), `distance` (first apply, if `set_distance`), and the Camera's `clip_end` (= `(max_distance + R) * far_clip_scale`, 0 leaves it alone) / `clip_start` (= `clip_end * near_clip_ratio`, 0 leaves it alone). Keys: `frame_margin` (1.1), `max_distance_scale` (1.0), `min_clearance` (4), `zoom_notches` (25), `far_clip_scale` (2.0), `near_clip_ratio` (0), `set_distance` (true). **Do NOT author `min_distance`/`max_distance`/`zoom_speed` beside it** -- it overwrites all three together, which is what keeps the zoom-coupled `pitch_at_*`/`tangent_at_*` curves where you put them. `shadow_distance` and `volumetrics_max_distance` are NOT derived: author them in the scene |

## Rendering

| Component | Keys (default) |
|---|---|
| MeshRenderer | `mesh_path` (key -> `meshes/<key>.yaml`), `material` (path, `{ base: ..., overrides }`, or inline -- see create-material), `materials` (per slot: list or `{ slot_name: material }`), `lod_bias` (1), `lods_enabled` (true), `affects_reflection_probes` |
| SkinnedMeshRenderer | `mesh_path`, `bones` (bone NAMES within the rig, in the mesh's `joints:` order; default = the mesh's own vertex-group names), `rig` (optional explicit path; default = the nearest ancestor, or the owner itself, carrying a `Rig`), `preserve_volume` (false; dual-quaternion skinning, Blender's option of the same name -- a twisted joint keeps its cross section instead of pinching). Sibling MeshRenderer has no `mesh_path` (material only) |
| DirectionalLight | `direction` (-1,-1,-1; the way light travels), `color`, `intensity` (1), `cast_shadows` (true), `shadow_intensity` (1). Only the first active one is used |
| PointLight | `color`, `intensity` (1), `range` (10), `cast_shadows` (true), `attenuation_constant` (1; here a falloff SHARPNESS, ~2-8 = crisper edge), `attenuation_linear`, `attenuation_quadratic` |
| SpotLight | PointLight keys + `direction` (0,0,-1, local), `inner_angle` (20), `outer_angle` (30; half-angles, degrees) |
| Hair | **Hair/fur grown from the faces of the mesh beside it** -- a companion to a `MeshRenderer` on the SAME object (that mesh is the scalp). `shape` (`ribbon` = flat strips, alpha-friendly, for dense fine hair / `tube` = solid N-gon, for a few thick stylised strands), `density` (20000; strands per SQUARE METRE of scalp, so it means the same thing on a head and a bear), `max_strands` (8000; a cap, the groom is thinned evenly not truncated), `length` (0.12 m), `length_jitter` (0.25), `segments` (8; points per strand), `thickness` (0.0012 m across at the root -- 0.001 is a human hair, 0.03 a chunky poly strand), `thickness_over_length` (`[[0,1],[1,0.25]]`; multiplies thickness root->tip), `cross_section` (2; ribbon only, crossed planes -- 1 vanishes edge-on), `sides` (5; tube only), `droop` (0.4; how far a strand falls, in multiples of its own length), `clump` (0.3) + `clump_density` (0.02), `curl` (0; helix turns) + `curl_radius` (0.01 m), `frizz_degrees` (6), `root_mask` (a PNG sampled by the scalp's UV: red thins, green shortens), `guides` (OPTIONAL -- an object whose descendants' `Curve` components shape the groom; with none the groom is purely procedural, which is the default. List, add, duplicate and delete them in the Hair component's Guides section; draw them in **Pen Mode** (entering it on the groom lands on a guide, and the Select tool switches to whichever curve you click)) + `guide_influence` (1) + `guide_count` (3), `wind_flexibility` (0.25; tip sway as a fraction of strand length in a 10 m/s wind -- this is what moves a groom, in the vertex shader, at NO per-frame cost; there is no motion in dead air) + `wind_frequency` (3), `simulate` (false; on = guide strands solved by physxcoopa's XPBD hair solver and colliding with the body -- set `wind_flexibility: 0` too, or the shader sway fights it) + `sim_guides` (64; only the guides are solved, so THIS is what the cost scales with, not density) + `weather_wind` (1; how much of the weather's wind reaches a SIMULATED groom) + the live solver tunables `sim_stiffness` (0.12; fraction of the way back to the combed pose per 1/60 s -- THE control for how alive hair looks; 0.05 or less for something loose like a tail) + `sim_stiffness_falloff` (1.6; higher frees the tips) + `sim_curl_hold` (0.25) + `sim_damping` (0.06) + `sim_drag` (0.6) + `sim_collision_thickness` (0.01 m) + `sim_friction` (0.4) + `sim_gravity` (1) + `collide_with` (`[]`; names of other objects a SIMULATED groom collides against -- empty collides with every nearby collider via the broadphase, same as cloth; naming objects skips the broadphase entirely and collides ONLY against them, which is cheaper and predictable; the groom's own collider, if it has one, is always included; a named object with no `Collider` warns and is skipped, never synthesized). Every `sim_*` key takes effect LIVE without re-growing the groom, `lod_screen_sizes` (`{x: 0.09, y: 0.035}`; each level halves the strand count, thresholds must descend) + `cull_screen_size` (0.012), `regenerate` (`on_change` / `on_load` / `manual`), `seed` (7), `material` (defaults to `shader: hair`, two-sided), `scalp_mesh` (empty = the sibling renderer's own mesh; a SKINNED scalp uses its SkinnedMeshRenderer's bind pose automatically, and a SIMULATED groom on one follows the deforming surface). Geometry is published as a locked `HairMesh` child under "Runtime" and never saved. See toyengine/hair/README.md |
| Volume | see create-fog-volume |
| SdfRenderer | `bounds_center`, `bounds_extent` (local box; keep tight), `material`, `cast_shadows`, `max_steps` (64), `surface_epsilon`, `normal_epsilon`, `smoothing` (blend between child shapes) |
| SdfShape | `shape` (`sphere` / `box` / `plane`), `params` (sphere x = radius, box = half-extents, plane x = offset), `rounding`, `op` (`union` / `subtract` / `intersect`), `blend`. One per object; children of an SdfRenderer |
| XraySubject | `enabled` (true). Marks this object -- and its whole subtree -- as one whose silhouette shows when it is hidden behind an `XrayOccluder`. The player, in a top-down game. Needs `xray_enabled: true` in the scene's `settings.render`; the look (`xray_mode` silhouette/outline/both, `xray_color`, `xray_thickness`, `xray_depth_fade`) is per-SCENE, not per-object, and every marked mesh merges into ONE silhouette with one outline. `enabled: false` on a child opts just that part out |
| XrayOccluder | `enabled` (true). Marks this object -- and its whole subtree -- as something an `XraySubject` may be seen THROUGH. Terrain, walls, roofs. **Both halves are required:** a subject hidden behind unmarked geometry stays hidden, which is how one pillar stays solid while the rest of the level does not |
| ViewBlockerFade | `fade_target` (1; 1 removes it), `fade_in_time` (0.18 s), `fade_out_time` (0.35 s), `cutoff_steps` (32; 0 = continuous), `keep_shadow` (true). Dissolves this object out of the way while its collider blocks the camera's view of an `XraySubject`, and restores it after. The material must already be `alpha_mode: CUTOUT` with a noise mask in `texture_alpha_mask` (`textures/masks/dissolve_noise.png`) and `alpha_cutoff: 0.0` -- the component owns the cutoff from then on. An alpha TEST, not transparency: the wall never becomes glass. `keep_shadow` (the default) keeps it casting its SOLID shadow while hidden -- it has not left the world, and losing the shadow pops the scene's lighting; it also stops the fade invalidating the static shadow caches. `keep_shadow: false` lets the shadow erode with it. Needs a collider, and `install_view_blocker_system()` (every Engine scene has it) |
| EnvironmentLight, ReflectionProbe, GiProbeVolume | parsed but only feed gfxcoopa's GI system, which toyengine does not run. Ambient comes from config `sky_*` |

## Navigation

Navmesh is built from the scene's colliders (static and kinematic; triggers and dynamic bodies
skipped) once the scene has a NavAgent. Configure it under `scene.settings.navigation` (or
config.yaml `navigation:`): `cell_size` (0.25), `cell_height` (0.1), `tile_size` (32),
`max_slope` (45), `bounds { min, max }` (default: fit colliders), `layers` (physics layers that
contribute), `agents: [{ name, radius, height, max_climb }]`, `areas: [{ name, cost, id }]`,
`rebuild_delay`, `max_path_requests_per_frame`, `repath_interval`, `repath_distance`,
`flow { rebuild_distance, max_distance, wall_penalty, bound_to_followers, mode (auto / exact /
hierarchical), exact_tile_budget, near_radius, lookahead_tiles, rebuild_interval }`,
`source_scan_interval`, `build_without_agents`, `debug_draw` (`Mesh`, `Grid`, `Tiles`, `Links`,
`Paths`, `Flow`, `FlowTiles`, `Agents`, `All`; shows in every debug_view), `debug_flow_stride`.
For big levels use `cell_size: 0.5`; flow mode `auto` goes hierarchical by itself. Full docs:
`libs/physxcoopa/physxcoopa/nav/README.md`; example scenes: `nav_demo` (A* + flow, small),
`nav_stress_demo` (hierarchical flow fields, 400 m).

## Loading screen

Every host (standalone and the editor's Play) launches into a loading state and holds it until
every streaming system has caught up, then reveals the scene. Configure it project-wide in
config.yaml's `loading:` section, or override it for one scene under `scene.settings.loading`
(same keys, layered engine default < config.yaml < scene): `enabled` (true), `spinner` (true;
draws the built-in white toyengine-block mark, false = overlay only), `background` (0,0,0; the
cover's fill colour), `spinner_color` (1,1,1), `corner` (`bottom_right` / `bottom_left` /
`top_right` / `top_left`; which corner the mark sits in), `overlay_ui` (`ui/<name>`, blank =
none; a project's own panel drawn over the built-in mark), `min_display_time` (0 s; never flash,
hold at least this long), `fade_in` (0.35 s), `fade_out` (0.35 s), `warm_up_timeout` (20 s; reveal
anyway so a stuck system cannot hang the game), `warm_up_budget_ms` (8 ms/frame; main-thread
budget streaming systems get while covered). `TOY_LOADING=0` forces it off for a headless
capture regardless of config. See toyengine/core/README.md's "The loading state".
