# Add tile terrain

`TileTerrain` (written `Terrain` in older scenes -- both load) generates its world from mapcoopa's
map data and builds every tile from a **tile set**: an object asset whose children are the pieces
(top quadrants, wall caps, walls, corners). The tile set is the whole form -- change `tile_set`
to change the terrain from rounded cliffs to square blocks. For a heightmap you sculpt, paint or
import, see the create-heightmap-terrain skill.

The world is **stored**: mapcoopa bakes it once into a `.tiles` file (`tiles:`, default
`terrain/<object>.tiles` beside the scene; baked automatically when missing), and from then on the
tiles are edited -- in the editor's Tile Mode, or by gameplay (`TerrainComponent::tiles`, then
`mark_dirty()`; water edits through `toyengine/world/tile_water.h`). The `generator:` block only
shapes a bake; delete the `.tiles` file (or use the editor's World Generator / Regenerate World)
to bake again after changing it. Each tile stores ground height, surfaces, biome, temperature,
moisture, water depth and river flow, and region / country ids. Water is drawn as smooth WaterBody
surfaces over sand beds (never as tiles); `water:` takes WaterBody keys.

Read **`toyengine/world/README.md`** (stored tiles, generation, tile sets, pieces, collision) and
copy from `assets/scenes/terrain/terrain_demo/scene.yaml`. Parser: `toyengine/scene/register.cpp`
("TileTerrain", alias "Terrain"); defaults in `toyengine/world/terrain_component.h` and
`terrain_sampler.h`.

## Minimal recipe

```yaml
- name: terrain
  components:
    - type: Transform
      position: { x: 0.0, y: 0.0, z: 0.0 }
      rotation: { x: 0.0, y: 0.0, z: 0.0 }
      scale: { x: 1.0, y: 1.0, z: 1.0 }
    - type: TileTerrain
      tile_set: objects/terrain/tileset_round   # or tileset_voxel (blocks), tileset_soft, tileset_rock
      # tiles: terrain/terrain.tiles            # the stored tiles (default); baked when missing
      generator:                # mapcoopa's own config keys; omitted = its standard map
        seed: 7                 # (what a bare `mapcoopa` run makes: 80 cells, continents),
                                # in the natural terrain model (terrain_model: classic for facets)
        natural: { mountains: 0.45, hills: 0.05, plateaus: 0.07 }   # landforms, normalised height
        grid_size: 64
        sea_level: 0.28
        shape: { shape: circle, diameter_m: 0 }   # rectangle | circle | triangle | continent | archipelago
      world_tiles: 320          # the map rasterised to 320 x 320 tiles (0: grid_size x tiles_per_grid_unit)
      tile_size: 1.0            # world size = world_tiles x tile_size
      height_step: 1.0          # = tile_size keeps the pieces cubic
      height_scale: 16.0
      water_inset: 0.5          # sea / lakes sit this many steps under the terrace they fill
      river_inset: 0.2          # rivers, nearer their bank tops
      water: { clarity: 2.5 }   # optional WaterBody look keys
      chunk_size: 32
      view_radius: 2            # chunks streamed around the main camera
      collision: true           # default; each chunk collides with what it draws
      material:
        texture_albedo: textures/terrain_atlas.png        # the default when omitted
        texture_metallic_roughness: textures/terrain_atlas_mr.png
```

Key groups: stored tiles (`tiles`); tile set (`tile_set`, `kind_tile_sets { <kind>: objects/terrain/tileset_x }` with
kinds grass, dirt, stone, sand, snow, rock, ice, moss, clay, ash, salt -- unlisted kinds
use `tile_set`); generation (`generator:` -- any mapcoopa config key, see
`libs/mapcoopa/assets/config.yaml`; plus `world_tiles` / `tiles_per_grid_unit`, `height_scale` -- bake only; the
old flat keys `seed`, `shape`, `sea_level`... still load); tiling (`tile_size`, `height_step`,
`chunk_size`, `view_radius`, `max_wall_steps`, `soil_depth_steps`, `max_chunk_jobs_per_frame`);
water (`water_inset`, `water:` WaterBody keys); collision (`collision`, `physics_material`); look
(`material`, separate from the tile set).

Old keys still load: `styles:` / `kind_styles:` (named sets per kind); `side_mesh:` / `sides:` /
`greedy_merge:` / `emit_bottom:` are retired (they fall back to `tileset_voxel` with a warning).
Write `tile_set:` in new scenes.

## Notes

- Chunks stream around the **main camera**: terrain_demo orbits the camera around a
  `focus_marker` object with a FreeMover so the user can travel. Big `view_radius` x
  `chunk_size` costs generation time.
- Collision exists only where chunks are live: keep physics within `view_radius` of the camera,
  and drop bodies from a height that gives the first chunks time to build (well under a second).
- Tile sets are object assets `assets/objects/terrain/tileset_*.yaml` (`tile_set: true`, one
  child per piece named by piece, each with a MeshRenderer `mesh_path`; optional
  `round_kind_corners: false` keeps kind boundaries square). Pieces live in
  `assets/meshes/terrain/<set>/`, the palette in `assets/textures/terrain/terrain_atlas*`. They
  come from `tools/gen_tile_styles.py` and `tools/gen_terrain_atlas.py` -- extend those
  generators (a new set is a new STYLES entry) rather than hand-editing their outputs. In the
  editor, *Duplicate as New Tile Set* copies a set with its own piece meshes to reshape.
- **Planets**: `planet: true` with `face_tiles` (tiles per cube-face edge; radius
  `2 * face_tiles * tile_size / pi`), `chunk_size` dividing it, and `gravity` (m/s^2). Everything
  stays loaded and the planet only starts pulling once every chunk is live, so bodies and the
  player can be placed above the surface at any side (position = direction * (radius + a few m)).
  Keep `face_tiles` modest (<= 128): every chunk is built at load, and a planet gives every one
  of them a collider -- `collision: false` (with `gravity: 0`) is most of the load time back for
  a globe nothing stands on. Reference: `assets/scenes/terrain/planet_demo`, a globe spun by the
  mouse (`Turntable` on the terrain object) in front of a fixed orbit camera that only zooms.
- Every chunk mesh carries coarser LOD levels (`lods:`, a list of `{ratio, screen_size}`
  coarsest last; `[]` turns them off). The defaults only coarsen chunks small on screen, so a
  ground-level camera is unaffected; they pay on planets seen whole and on terrains with a
  large `view_radius`. Seam vertices are pinned through every level, so chunks at different
  levels never crack.
- **Editing at runtime**: `TerrainComponent::raise_at(world, radius, delta)` /
  `set_tile_height()` / `paint_tiles()` move the ground and queue the water, which then flows in
  (or off) over the next frames at `water_settle_budget` tiles each -- sea, lakes and rivers
  alike. `raycast_tiles()` picks the tile under a ray with no colliders needed. A `TerrainDigger`
  component does it from the mouse in `dig_demo` (sea, lakes and a river at arm's length). It is
  gameplay, so it runs in Play, not in the editor's edit mode -- in the editor, Tile Mode's
  brushes move ground through the same operations.
- Large terrains want shadow tuning in scene settings (terrain_demo uses `shadow_fit: focus`,
  `shadow_focus_radius`, `shadow_distance`).

## Verify

```sh
FRAMES=240 .claude/skills/create-scene/scripts/render_scene.sh <scene>    # chunks need frames to stream in
./build/tests/toyengine_tests --suite terrain_chunk
./build/tests/toyengine_tests --suite styled_tiles
ctest --test-dir build -L gpu -R terrain_render
ctest --test-dir build -L gpu -R planet_world     # planets
```

Look for holes (chunks not yet streamed -- give more frames), seams between chunks, the tile set
per kind applied where expected, and bodies resting on the ground rather than falling through.
