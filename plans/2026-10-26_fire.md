# Fire: a propagating environmental state

> **Status: designed, nothing landed.** Additive — a new `toyengine/fire/` area. Nothing in
> `weather/`, `env/` or `world/` changes behaviour; fire *publishes into* the env field and
> *reads* wind and wetness from it.
>
> **Difficulty: high.** Three stages, each independently shippable and verifiable. One new
> SSBO binding, one new surface cover layer, one new camera-following field, two new
> components. The existing `campfire.yaml` keeps working untouched and is the regression target.

## Why

Weather is global. `toyengine/env/` added *local* influences — a rotor's downwash, a vent, a wet
patch. Fire is the next thing along that axis and the first that **propagates**: it moves
through the world under its own rules rather than being placed.

Today there is no fire simulation of any kind. Greps for fire / burn / flame / ignite / combust /
scorch / char across `toyengine/`, `libs/`, `assets/` and `editor/` find **no** component,
system, shader, YAML key or asset. What exists is presentation only:

- `assets/objects/props/campfire.yaml` — the single shipped fire asset: 331 lines, 18 children,
  five `ParticleSystem`s hand-tuned per-prefab.
- `ParticleSprite::Flame`, `Spark`, `Puff` (`toyengine/render/particle_types.h:46`); `additive`,
  `emissive`, `toon_bands`.
- `toyengine/particles/light_flicker.h` — the only fire *logic* in the engine. Its `dimmer`
  (single writer: `WeatherReactor`) is how rain already puts a campfire out.
- `assets/audio/sfx/fire.wav`, referenced from exactly one scene.

So every candle is a hand-built prefab, and nothing can catch fire. The intended outcome:

1. **One scene-level block defines what fire looks like**, so a candle is five lines of YAML
   rather than a 331-line prefab.
2. **Fire spreads** between neighbouring vegetation and props, carried downwind and stopped by
   wet ground — the payoff for having built the env field.

## The fact that forces the architecture

"Flames spread between neighbouring meshes" means **two different mechanisms**, because the
engine stores the two kinds of mesh completely differently:

| | Procedural scatter (grass) | Painted instances (trees, props) |
|---|---|---|
| Source | `ParticleSystem { mode: scatter }`, `toyengine/particles/terrain_scatter.h` | `toyengine/instance/`, `InstanceRecord` (48 B) |
| CPU records | **none** — regenerated from `hash(seed, chunk, cell)` | real records in a sparse chunk grid |
| Spatial query | none | `query_radius()`, `any_within()`, `at(InstanceRef)` |
| Remove / swap one | **impossible** — no exclusion mask anywhere | `erase()`, `add()`, `Hidden` flag, prototype swap |
| Per-instance GPU channel | none | none |

Both paths funnel into one contract (`MeshInstanceBatch` in `toyengine/render/particle_types.h`)
whose per-instance payload is **three `mat4`s and nothing else** — vertex attribute locations
4-15, all consumed. There is no spare channel on either path.

**Therefore:** a blade of grass can never know it is on fire. It can only read a value from its
own position. A **world-space field is the only possible substrate for grass**, and painted
instances layer true object-to-object ignition on top of it.

`assets/shaders/foliage_surface.glsl` already proves the pattern — it keys wind off
`v.model[3].xyz`, the instance's own root, so a scattered plant gets a per-instance value
*derived from position* without carrying any state.

## Architecture — `toyengine/fire/`

A new area beside `weather/`, `env/`, `water/`, `world/`. Registered the same way
(`register_fire_components()` from `Engine`'s ctor; `install_fire_system()` from
`prepare_scene_()`). CMake needs no edit — it globs.

### `fire_profile.h` — the look, scene-level

`scene.settings.fire`, parsed exactly as `scene.settings.weather` is (a per-scene
`fkyaml::node` kept in `Engine::scene_settings_` and handed to the system at install).

```yaml
scene:
  settings:
    fire:
      enabled: true
      # --- The LOOK: one place that defines fire everywhere in this scene ---
      flame_color:     {r: 1.0, g: 0.45, b: 0.10}
      flame_tip_color: {r: 1.0, g: 0.86, b: 0.45}
      smoke_color:     {r: 0.22, g: 0.21, b: 0.20}
      ember_color:     {r: 1.0, g: 0.32, b: 0.05}
      char_color:      {r: 0.05, g: 0.04, b: 0.04}
      light_color:     {r: 1.0, g: 0.52, b: 0.18}
      light_per_intensity: 420      # PointLight intensity at intensity 1
      flicker_amount: 0.32
      flicker_speed: 7.0
      smoke_density: 1.0
      # --- The SIM ---
      spread_rate: 1.0        # cells/s the front advances through full fuel
      burn_rate: 1.0          # how fast a lit cell consumes its fuel
      wind_spread: 1.0        # how hard env wind biases the front downwind
      wet_resistance: 1.0     # how hard env wetness blocks ignition
```

Mirrors `weather_profile.h`'s shape: a `Settings` struct, `parse_settings()`, `to_node()`.

### `fire.h` — two components

**`Fire`** — an authored source. Candle, campfire, torch, brazier.

```yaml
- type: Fire
  intensity: 0.5      # candle 0.08, campfire 0.5, bonfire 1.0
  radius: 0.6         # m, the flame's own size
  eternal: true       # a candle never burns out; false consumes fuel
  ignites: true       # can it light neighbours
  effects: true       # build flames/smoke/embers/light from the scene's fire look
```

`effects: true` is where the global settings pay off: `FireSystem` spawns the particle children,
the `PointLight` and its `LightFlicker` as **runtime objects** under one `Fire` root, via
`toy::scene::spawn_runtime_root()` — the same mechanism `WeatherSystem` uses for rain, so they
are never written to the scene file and the editor shows them locked under **Runtime**.

`campfire.yaml` stays working untouched and becomes the regression target: a `Fire` with
`effects: true` should look close to it without the 331 lines.

**`Flammable`** — makes an object catchable.

```yaml
- type: Flammable
  spreadability: 0.7   # 0 never catches; also how much fuel it lays into the field
  fuel: 12             # seconds of burning before consumed
  ignition_time: 1.5   # s of exposure before it lights
  on_burnt: char       # char | remove | prefab:<path>
```

`on_burnt: char` is the default and the cheapest: the object stays and is blackened by the
surface layer below. Mesh *fracture* (`toyengine/destruct/`) is deliberately not reused — a
burnt tree chars, it does not shatter into Voronoi cells.

### `fire_field.h` — the spreading grid

Modelled on `toyengine/world/snow_field.h` (toroidal world-cell window, scrolled by moving the
window with no copying, version-bumped, with a CPU mirror of what the shader reads), with two
deliberate differences:

| | SnowField | FireField |
|---|---|---|
| Grid | 512² @ 0.1 m = 51.2 m | **256² @ 0.25 m = 64 m** |
| Layers | 1 (trench), unorm16 | **2 (fuel, burn), unorm8** |
| Bytes | 512 KiB | **128 KiB** |

**Why coarser.** `SurfaceWorldData::upload()` is whole-buffer — a single moving deformer costs
the entire field. Snow gets away with it because trenches are mostly static and refills are
paced to `kRefillStep = 0.05 s`. **Fire changes every frame.** At snow's dimensions that is
512 KiB × 2 frames-in-flight × 60 fps ≈ 61 MiB/s, continuously. At 256²/unorm8 it is ≈ 15 MiB/s,
and only `burn` needs re-uploading per frame — `fuel` stays version-gated.

Fire does not need 10 cm resolution; 25 cm is finer than a grass tuft.

### `fire_system.h` — order **44**

Deliberately **before** `EnvSystem` (45), not after. Fire's heat and updraft then land in the
same frame's env gather, and fire reads last frame's wind/wetness — one frame of wind lag is
invisible, whereas a frame of lag on its own heat output would make the two systems disagree.

Per frame:

1. **Sources** — walk `Fire` components, ignite their field cells, keep their runtime effects in
   step with `intensity`.
2. **Spread** — the budgeted resumable frontier walk. **Reuse the shape of
   `toyengine/world/terrain_water.cpp:58` `spread()`**: a persistent `std::deque<glm::ivec2>`
   frontier and a per-call cell budget, so the walk is bounded per frame and resumes where it
   left off (`begin_settle()` / `step_settle()` is the documented precedent, budgeted by
   `TerrainComponent::water_settle_budget`). Swap the water-level comparison for an ignition
   threshold; bias the 4-neighbour step downwind by `env::wind_at()`; reject cells where
   `env::wetness_at()` exceeds `wet_resistance`.
3. **Consume** — lit cells burn fuel down; spent cells decay to char.
4. **Painted instances** — `InstanceSetData::query_radius()` around hot cells finds trees and
   props; a CPU-side burn table keyed by `InstanceRef` tracks exposure and fuel; on burn-out,
   `on_burnt` applies (`erase()` + `add()` with a charred prototype, which swaps the streamed
   collider too).
5. **Publish** — aggregate nearby fires into `EnvSource`s carrying `temperature` and a real
   vertical updraft.

**Two traps in that last step**, both found during exploration:

- `kMaxEnvSources = 8` (`toyengine/env/env_field.h:48`). A hundred candles cannot each be a
  source — the system must aggregate.
- The overflow cull in `toyengine/env/env_system.cpp` ranks by **`speed × radius`**, so a
  pure-heat source with zero wind sorts last and is dropped first. Giving fire sources a genuine
  updraft fixes this *honestly* (hot air does rise) rather than by special-casing the cull.

`EnvSource::temperature` is currently plumbed end-to-end with **zero consumers** — its only
exercise is a unit test (`tests/engine/unit/env_field_test.cpp:220-235`). Fire is its first
real one.

### The surface layer — char and embers

`assets/shaders/gfx/surface/fire.glsl`, built as a cover layer directly analogous to
`snow.glsl`:

- `gfx_fire_apply(s, geo_n, p)` — darkens albedo toward `char_color`, raises roughness, and adds
  `ember_color` through a noise mask where burn is high.
- Emissive is the mechanism that already works: `gbuffer_fs.glsl:193` writes
  `out_emissive = vec4(s.emissive, float(material.surface_ext.w))`, bloom picks up anything over
  threshold, and `snow.glsl:107` is the shipped precedent for a cover layer writing `s.emissive`
  from `gfx_surface_fragment()`. **G3's alpha is not free** — it carries the toon code and the
  outline mask.
- Called from `gbuffer_fs.glsl` beside the snow block, gated on the field being present.
- Material opt-out: `ext.z |= 4u` for `burns: false` (bit 0 is `snow: false`, bit 1 is the
  parked puddle plan's `wet: true`; `ext.z` has exactly one writer and one reader today).

Grass gets this for free, because it is an opaque material. **That is how a grass fire reads on
screen** — no per-instance state, just the field sampled at the plant's root.

### GPU plumbing

- `SurfaceWorldData` gains SSBO **binding 3**. Confirmed free: the surface-world set has only
  0 (UBO), 1 (occlusion heights), 2 (snow trench) today, and `DescriptorLayoutBuilder` has no cap.
- `vec4 fire; ivec4 fire_dims;` appended to `SurfaceWorldUBO` **after `terrain[]` and `env[]`** —
  the layout rule the header already states — with its `static_assert` updated.
- `gfx_fire_at(vec2)` in `assets/shaders/gfx/surface/world.glsl`, mirroring `gfx_world_trench()`'s
  toroidal read.

Keep `fire_field.h`, `world.glsl` and `surface_world.cpp` in step; the repo pins this three-way
mirror by test for the existing channels.

## Staging

Each stage is shippable on its own and gated by its own tests.

| Stage | Scope | What it buys |
|---|---|---|
| **1** | `fire_profile` + `Fire` + runtime effects + env heat/updraft | Candles and campfires from one global look block. No spread. |
| **2** | `FireField` + spread + `fire.glsl` surface layer + GPU plumbing | Grass burns, carried downwind, stopped by wet ground. |
| **3** | `Flammable` + painted-instance ignition, burn-out, charred swap | Trees catch from each other and are consumed. |

## Demo

Extend `assets/scenes/effects/environment_demo/` rather than building a new scene: its clearing
already has a dense grass floor, a pine ring and a preset switcher, which is an ideal fire
testbed. Two new presets — **Campfire** (stage 1) and **Grass Fire** (stage 2/3, igniting at the
centre and running downwind toward the treeline).

The existing bottom bar takes eight buttons; this does not need the parked

## Verification

**Unit** — `tests/engine/unit/fire_field_test.cpp`:
- spread is deterministic and budget-independent (same end state, fewer frames);
- fuel is consumed and a spent cell does not re-ignite;
- `wetness_at()` above `wet_resistance` blocks ignition;
- wind bias moves the front downwind, and reverses with the wind;
- the toroidal window scrolls without losing lit cells inside it.

`tests/engine/unit/fire_profile_test.cpp` — parse/emit round-trip, as `weather_profile` has.

**GPU** — `tests/engine/gpu/fire_render_test.cpp`:
- a `Fire { effects: true }` lights the scene, and its runtime children are marked
  `RuntimeObject`;
- `FireField::burn_at()` agrees with `gfx_fire_at()` across a sample grid (the CPU/GPU mirror,
  in the assertion style `env_render_test` uses);
- a grass fire chars the ground it has passed and leaves unburnt ground beyond the front;
- a wet patch stops the front;
- a scene with no fire packs no field and every `gfx_fire_*` early-outs — the no-regression guard.

**Visual** — captures of the campfire preset against `campfire.yaml` side by side (stage 1), and
a three-frame sequence of the front advancing (stage 2). A screenshot is the only thing that
proves fire reads on screen.

**Build discipline** — `toyengine/render/surface_world.h` invalidates nearly every TU, so all
header edits land before the first build of a stage. Per the project build rules: `-j4` for
builds, `-j2` for ctest, one heavy job at a time, `run_in_background` rather than detaching, and
the full sweep once at the end.

**Gate before stage 1:** the full suite has not been confirmed green since the env/preset work
landed — that run was orphaned when a session exited. Confirm it first, so fire is not built on
an unverified base.

## What this deliberately does NOT do

- **No fire → damage or health.** Burning is a world state; what it does to a character is
  gameplay, and nothing in the engine owns that yet.
- **No volumetric smoke.** Particles only, as the campfire does today.
- **No per-instance GPU burn state.** It would need a 4th `mat4`-sized slot at locations 16-19 on
  `InstanceData`, +16 B on every instance engine-wide and edits to all five backbones. The field
  makes it unnecessary. (`InstanceRecord::seed` is a reserved, persisted, per-instance 32-bit
  slot with no consumer — the natural home if this is ever wanted; the instance README names
  the gap.)
- **No world-scale fire.** The field is a 64 m window around the camera, exactly as snow is;
  fire outside it is not simulated.
- **No fire audio beyond looping `fire.wav`.** There are no crackle/ignition/extinguish one-shots
  in `assets/audio/sfx/`, and authoring them is a separate job. Note that nothing links
  `WeatherReactor` to audio — its `target:` accepts only `lights`, `effects`, `children` — so a
  fire system must start and stop its own loop.
